# Decisions log

## 2026-09-17 — Art direction (from the Cowork session)
- Rejected: glossy 3D "Pixar" pets (too mainstream), gummy/vinyl/chrome/voxel/clay/shadow directions, felt-on-low-poly.
- Chosen: cozy pixel art. Habitats on a 160×120 grid, pets as 80×80 sprite strips, 8 fps stepped motion, ambient FX at 60 fps.
- Gen 1 species: fish (bowl → tank), hamster (cage → terrarium), frog (pond → jar), chicken (brooder day 0–7 → coop).
- The habitat IS the widget: transparent frameless always-on-top window, resizable S/M/L, minimizes to a tray chip.
- The pantry (feeder object in each habitat) is the visible away-mode gauge. Feed = burn 25 $FEED. Decay 100/60h. Death after 24h at zero.
- Phase 0 local only; Phase 2 moves authority to Solana (Metaplex Core + Anchor feeder program + keeper crank).

## 2026-09-17 — Phase 0 scaffold and architecture contract
- Stack pinned: Tauri 2.11 (Tauri 3 is alpha on crates.io; not used), Vite 8.3, TypeScript 5.9 (TS 7 native port skipped for Vite/Vitest compatibility), Vitest 3.2, PixiJS 8.20, Zustand 5 (vanilla store, no React), Howler 2.2, Playwright 1.63.
- `docs/ARCHITECTURE.md` is the binding module contract so sim / shell / render / ui can be built in parallel. Dependency direction: sim ← app ← (render, ui) ← main; platform is only imported by app, ui, main.
- Added `lastReconciledAt` to `PetState` (not in the Blueprint). Reason: `reconcile()` must walk only forward from the last applied time so a pantry deposit made after a hunger crossing is not applied retroactively, and so reconcile is idempotent. Persisted with the pet.
- `Ledger` gained `debit(n)` / `credit(n)` next to `burn(n)` because pantry deposit/withdraw moves tokens rather than destroying them. Phase 2 maps them to `pantry_deposit` / `pantry_withdraw`.
- Auto-feed trigger is `hunger <= PANTRY_TRIGGER` (30), evaluated at the exact crossing timestamp. A fresh pet at 100 with 500 in the pantry gets 8 auto-feeds in 10 days (42 h, then every 27 h) and ends with 300 in the pantry; the Blueprint's "~250 or less" is only reached when the pet starts below full.
- Window padding: `WINDOW_PAD = 24` CSS px on every side (window = 160s+48 × 120s+48), read as "24 px padding for the HUD and shadow" per side so the hover pill fits above the bowl without covering it.
- Click-through: Rust polls the global cursor position and toggles `set_ignore_cursor_events` against hit regions the frontend sends, because a webview that ignores cursor events cannot see the cursor come back. Documented in the contract as the macOS workaround.
- Assets: Vite `publicDir` is the repo `assets/` folder; a build plugin deletes `dist/reference` so the 1024 px references never ship. Placeholder layers/strips are generated by `tools/gen_placeholders.py` and stamped PLACEHOLDER.
- Dev clock: `now() = Date.now() + settings.devClockOffsetMs`, persisted, so "fake the clock and relaunch" works for acceptance testing.
- Playwright drives the Vite build in a browser against `src/platform/browser.ts` (a mock of the Tauri boundary) because WebDriver for Tauri is not available on macOS; the real window is verified by hand and by the Rust-side integration.

## 2026-09-17 — Contract critique (four-lens review before the parallel build)
- 52 findings folded into `docs/ARCHITECTURE.md` and the shared type files. The ones that change behavior:
- Events are emitted on a half-open window `(lastReconciledAt, now]`; auto-feeds on the closed window `[lastReconciledAt, now]` so a pantry deposit can feed at `now`. Every mutator reconciles first and returns its events. Clock going backwards is a no-op.
- `withdrawPantry` is allowed on a dead pet (otherwise $FEED is stranded); `balance + pantry + feedBurned` is conserved.
- Rust owns the top-level `positions` key in `settings.json`; TS only writes `doc`. Sharing one nested document would let TS autosaves clobber saved window positions.
- The Rust cursor poller also emits a `pointer` event: once the window ignores cursor events the webview can never see the cursor leave, so hover state has to come from Rust.
- Tray: `showMenuOnLeftClick: false`; left click toggles visibility, right click opens the menu. Global shortcut fires on key press only. Tray chip is 18 px (36 on Retina) because macOS status items are 18 pt tall.
- Pixel grid: everything except the drop shadow renders into a 160×120 RenderTexture that is upscaled by the integer scale, instead of relying on `roundPixels` (which snaps to device pixels, not to the big-pixel grid).
- Dead vs memorial: `SceneView.phase` = alive → dead (belly-up, fog) → memorial (empty bowl with a flag) once the user dismisses the death card (`latches.deathAcknowledgedFor`).
- Hit regions use the habitat's opaque bounding box (x 40..123, y 4..118 on the grid), not per-pixel alpha. Good enough for the bowl; revisit for the cage.
- Auto-feed trigger is inclusive (`hunger <= 30`); identical timing with continuous decay, and a pet exactly at 30 is fed.
- `hidden` (minimized to tray) is runtime-only; relaunch always shows the habitat.
- `dev.skipOnNextLaunch(ms)` arms a pending clock skip so the "quit, fake the clock, relaunch" acceptance step produces the montage.
- Acceptance math: a fresh pet needs +3d then +12h to die; 10 days with 500 in the pantry leaves 300.

### ui
- HUD/tray/speech derive their models locally (`src/ui/model.ts`: hunger label thresholds, `pantryDays`, `SceneView` for the chip) instead of importing `src/app/view.ts` or `src/sim/index.ts`, so `src/ui` typechecks and tests independently of the sim/app builders. The formulas are the contract's; if the contract changes, both copies change.
- The pill sits inside the top pad (y 4..20, bottom edge 4 px above the grid top at 24), centered on the habitat opaque rect; `getRects()` extends it down to `habitatHitRect().y` (the bowl's opaque top, 24 + 4·s) so the whole gap is inside a hit region. The caption sits 4 px below the opaque bottom, clamped inside the window.
- HUD show/hide uses `visibility` + a `steps(4)` 8 px translate (2 px per step, integer offsets) rather than `display:none`, so the pill stays measurable for layout while hidden; `prefers-reduced-motion` removes the transition entirely.
- Modal overlays (pantry dialog, memorial card, montage) are positioned inside `scene.habitatHitRect()` and sized to it (`min(240, hit.w − 8)` wide), so they need no extra hit regions: the habitat rect is always sent to Rust. `computeHitRegions` therefore stays `habitat + HUD + dev panel` as the contract says.
- Interactive overlays stop `mousedown`/`pointerdown` propagation (no accidental window drag) and also swallow `contextmenu` (right-clicking a dialog/dev panel does not pop the tray menu; right-click on the habitat still does).
- `mountMemorial` self-subscribes to the store (`!alive && latches.deathAcknowledgedFor !== pet.id`) so main.ts does not have to drive `setDead`; `setDead` remains exposed and is idempotent.
- Speech: `bite` fires per flake, so `fed` lines never queue (only the first bite within a 15 s window speaks); hunger/starving/idle/wake lines queue at most one (newest wins) and flush when the cooldown expires. `sayFrom('wake')` is the montage follow-up hook.
- Tray: the chip repaints when species / label / alive / phase / chip size change; tooltip and `setMenuState` are sent only when their content changes (each is one IPC call). `wireTray` also forwards `settings.muted` to `audio.setMuted` since the tray owns the Mute item.
- Dev panel: night override is a 3-way select (follow / day / night) mapped to `setNightOverride(null | false | true)`; species select lists every species/habitat pair with only `fish/bowl` enabled. The 10-day dry run prints `+1d 18h  <line>` offsets from `now()`.
- Audio: Howler sounds are created lazily per `/audio/<species>/<name>.ogg`; `onloaderror` logs once, unloads and blacklists the URL so a missing file never retries. No audio assets exist yet, so every load is currently a logged no-op.

### sim
- Tests first: `docs/SIM-TESTS.md` items 1–33 are implemented under those numbers in `src/sim/{hunger,feed,reconcile,ledger,pet}.test.ts`, plus `purity.test.ts` (regexes every non-test `src/sim/*.ts` import specifier and fails on anything not starting with `./`). `src/sim/test-helpers.ts` holds mulberry32 and the shared `fresh()` fixture; it is test-only but lives in `src/sim` so the purity rule covers it.
- Every computed timestamp (crossing, zero, death, dying-soon) is `Math.round`ed, for the default constants too. That is what makes reconcile path independent (item 14) and idempotent at event times (item 15) regardless of float noise in `100 / 60`; `hungerAfter` stays a float.
- `reconcile(state, now)` is a no-op returning the same object only for `now < lastReconciledAt` (strictly backwards) or a dead pet. `now === lastReconciledAt` runs the walk: the half-open event window is empty, but an auto-feed at `t* = from` still applies. This is required by `depositPantry`'s second reconcile at `now` (contract: "may auto-feed at now") and by item 19/20; the contract's "no-op when now <= lastReconciledAt" would silently drop the deposit-rescue feed. Deviation recorded in the build report.
- Item 24 (alive-at-t* guard) as written is unsatisfiable: `t* = max(from, crossing) >= from`, so with `from < zero + 24 h` a funded pantry always feeds (that is the rescue case, item 20). The guard can only trigger for a hand-built state with `from >= death` that is still flagged alive. The test uses that state (`lastReconciledAt = Z + 25 h`), asserts no auto-feed, pantry untouched, and the pet reconciled to dead with `diedAt = Z + 24 h`; the `died` event is not emitted because it lies at or before `from`.
- `feed()` sets `lastReconciledAt = max(now, reconciled.lastReconciledAt)` rather than exactly `now`, so the `lastReconciledAt >= lastFedAt` invariant survives a backwards clock (reconcile is a no-op then and would otherwise be undercut).
- `withdrawPantry` calls `reconcile` for every pet (a no-op for dead ones) and `credit(moved)` even when `moved === 0`; `depositPantry` on a living pet always calls `debit(moved)` (possibly 0) as its single ledger call; on a dead pet it returns `moved: 0` without touching the ledger. `LocalLedger`'s constructor also rejects non-integer/negative balances.
- `projectedDeathAt` reuses `reconcile` (to `max(now, lastReconciledAt)`, then to `MAX_SAFE_INTEGER`) instead of a second walk, so it can never disagree with what reconcile will do. Auto-feeds are skipped when a constants override sets `FEED_COST <= 0` (would loop forever).
- `newPet` draw order from the rng: id, rarity, personality, name (name draw skipped when `opts.name` is given). Species name pools (20 each) and the starter habitat per species (`fish→bowl, hamster→cage, frog→pond, chicken→brooder`) live in `src/sim/pet.ts`.
- App store: `hunger` is derived at `max(now, pet.lastReconciledAt)`, so after `dev.resetClock()` the HUD keeps the hunger the pet already reached instead of snapping back to the anchor value until real time catches up (the state itself never moves backwards).
- `lastFeedEvent` for auto-feeds uses only the "within the last 60 s" test, not the additional `at > previous lastReconciledAt` test from the contract: reconcile never re-emits an event, and a deposit made in the same millisecond as the last tick feeds at `t* = from`, which the strict test would drop (it happens deterministically under fake timers).
- `recentEvents` is set by any reconcile (boot, tick, feed/deposit/withdraw/dev) whose covered span exceeds 60 s, and left untouched otherwise, so a wake after hours also produces the montage list. `boot()` routes its catch-up events through `decide()` like a tick, so "has died" is notified on relaunch as well as shown in the montage.
- `decide()` adds an `alive` guard to "Pantry is almost empty." (a dead pet's leftover pantry never warns). Everything else follows the contract, including re-firing for each distinct low pantry value.
- Persistence: leading + trailing throttle per file (first save in a 500 ms window writes immediately, a burst coalesces into one trailing write); `flush()` fires pending writes and awaits them. `pet.json` is validated structurally (version 1, integer balance >= 0, latches shape); an invalid file starts a fresh pet with a console warning rather than crashing. Settings merge field-by-field over defaults; the graveyard drops malformed records.
- `dev.setSpecies` accepts only `fish/bowl` in Phase 0 and logs a warning otherwise. `dev.forceState('dead')` withdraws the pantry, marks the pet dead at `now` and emits a synthetic `died` event so the notification and death card fire. `newPet()` dedupes graveyard records by `(id, bornAt)` because ids are 4-digit random.
- `createAppStore(platform, opts?)` takes an optional second argument `{ rng, persistence }` for tests; the one-argument form matches the contract.

### shell
- Click-through is a Rust `std::thread` polling `app.cursor_position()` every 50 ms against the hit regions the frontend sends; `set_ignore_cursor_events` is toggled only on change and a `pointer {inside,x,y}` event is emitted on every change and at poll rate while inside. Verified in tauri-runtime-wry 2.11.4 that `set_ignore_cursor_events` is dispatched through the event-loop proxy (and tao additionally hops to the main dispatch queue), so no `run_on_main_thread` is needed. Rationale block lives at the top of `src-tauri/src/hittest.rs`.
- Cursor conversion: tao reports the cursor in physical px scaled by the *primary* monitor's scale factor while `outer_position` is scaled by the *window's* scale factor, so each is divided by its own factor before subtracting. Identical to `(cursor - outer_position) / scale_factor` on one monitor; correct on mixed-DPI setups.
- With no hit regions registered nothing is ignored and every point over the window counts as `inside` (boot-time default). The browser mock applies the same rule to DOM `mousemove` so hover behaves the same in Playwright as under Tauri.
- Window geometry is computed in logical px. `set_scale` keeps the bottom-right corner fixed; its first call restores `positions[monitorKey]` (preferring the monitor the window is on, then any connected monitor with a saved entry) or defaults to the primary work area's bottom-right minus 24 px; result is snapped/clamped and persisted, so the very first launch already has a saved position. `monitorKey = "<name|unknown>@<logical w>x<logical h>"`.
- `settings.json` layout: TS owns `doc`, Rust owns `positions` (`{ "<monitorKey>": { "x", "y" }, "last": "<monitorKey>" }`, top-left in logical px; `last` is the monitor key persisted most recently). Rust merges into the shared plugin store instance and calls `save()`; TS loads stores with `autoSave: false` and saves explicitly after every `set('doc')`.
- Move settling: `WindowEvent::Moved` records a timestamp; one helper thread waits for 150 ms of silence, snaps to the work-area edges within 16 px, clamps, repositions only if different, persists and emits `window-moved`. Self-inflicted moves are ignored two ways: `Moved` at the position Rust just set (±1 physical px) and any `Moved` within 250 ms of a programmatic resize/reposition (a resize alone produces an intermediate `Moved` on macOS).
- `show_window` only calls `WebviewWindow::show()`; with `ActivationPolicy::Accessory` this orders the window front without activating the app. `set_focus` is never called anywhere. The 10 s safety timer, the single-instance callback and `show_window` all mark the window as shown/visible; the poller idles while hidden and emits one `pointer { inside: false }` when the window is hidden with the cursor inside.
- Tray: the config-declared tray (`id: main`, `showMenuOnLeftClick: false`) is the only tray icon; Rust attaches a `Menu` whose item ids are exactly the `TrayAction` strings. Check items toggle themselves natively on click; TS re-syncs them through `tray_set_menu_state` on every settings change (`Notifications` is checked when `notificationsMuted` is false). Left click `Up` emits `toggle-visibility`; right click opens the menu natively; `popup_menu` shows the same menu at the cursor.
- Commands take flat camelCase args (`tray_set_menu_state` receives the `TrayMenuState` fields directly, matching the contract's "Args = TrayMenuState"); the chip is sent as `number[]` per the contract (5184 numbers for 36 px, well under any IPC limit).
- Clock: `wallMs` is `SystemTime` epoch ms, `monoMs` is `Instant` ms since process start (`CLOCK_UPTIME_RAW`, frozen during sleep); a 5 s sampler emits `wake` when wall drift exceeds monotonic drift by more than 5 s.
- Global shortcut `Cmd+Shift+P` is registered at plugin build time and emits `toggle-visibility` only on `ShortcutState::Pressed`. Plugin order: single-instance, store, notification, autostart, global-shortcut, positioner (positioner is installed but unused in Phase 0).
- Capabilities are minimal: `core:default` (events, window getters, tray/menu defaults), start-dragging, show, hide, and the store plugin's load/get-store/get/set/save. Everything else goes through Rust commands.
- Browser mock: `#app` is the "window" (inline width/height at the contract size, geometry from its bounding rect), `#mock-tray` is a fixed 22 px canvas whose backing store is the chip size (18/36) with `image-rendering: pixelated`, `#mock-menu` is a DOM menu of every `TrayAction` at the last mouse position (checks/labels/disabled from the last `setMenuState`), storage is `localStorage` `webpets:<file>` with an in-memory fallback when storage is blocked. `window.__webpetsMock` is typed in `src/platform/mock.d.ts` as optional (absent under Tauri).

### render
- Pixel grid is structural: every slot except `shadow` is drawn into a 160×120 `RenderTexture` (nearest, resolution 1) and that one texture is drawn at (24, 24) with `scale = s`; FX use float positions inside the RT and become big pixels for free. `roundPixels: true` stays on as a safety net only.
- Drop shadow is two black-tinted copies of the habitat RenderTexture offset by 1 and 2 grid px (alpha 0.16 / 0.10), drawn in CSS px under the habitat sprite. The contract said "stepped 2-tone offset rect"; a rect looks boxy under a round bowl, and a tinted silhouette is still stepped, 2-tone and blur-free.
- The concept bowl (`assets/habitats-160x120/fish-bowl.png`, used as `bg`) has a fish painted into it. Until the layered art lands the placeholder `medium.png` heals that patch with opaque water sampled from the same rows (`painted_fish_box` in `tools/gen_placeholders.py`), and `memorial.png` removes it too, so the live sprite is the only fish. `pantry.png` has an opaque dark interior so the concept's painted flakes do not show through an empty feeder.
- Manifest geometry refined from the art (kept in sync with `src/species/fish/layout.ts` by `layout.test.ts`): `waterShape = {cx 81, cy 58, rx 40, ry 42, surfaceY 23, floorY 96}` (the contract's ry 37 gave a zero-width surface row; the water is x 59..104 at the surface and x 41..121 at the widest), `pantryRect = {93, 5, 18, 15}` (the inner box of the clip-on feeder at x 92..111, y 4..20). `opaqueRect` kept at the contract's `{40, 4, 84, 115}` (measured alpha bbox is 1 px smaller; harmless for a hit box).
- `pantry_fill` crop: the sprite's `Texture` is created with `dynamic: true`; on change the `frame` Rectangle is mutated in place and `texture.update()` is called (Pixi 8's `frame` is readonly and `updateUvs()` alone does not re-measure the sprite; `update()` does both).
- Buffer-backed FX textures (bubbles, flakes, sheen) pass `format: 'rgba8unorm'` explicitly: Pixi defaults a `Uint8Array` `BufferImageSource` to `bgra8unorm`.
- Sprite player: repeated `play(current)` and `play(returnTo)` while a one-shot is mid-way are no-ops, so the behavior can keep reporting `idle` while the 4-frame `eat` finishes. States with no strip fall back to bob/squash/flip transforms with integer edges (scale.y 0.75 → 60 px, −1 for belly-up).
- Fish behavior: figure-eight is a Lissajous target (`sin(t)`, `sin(2t)`) the fish chases at ≤ 1.5 px/tick with an rng wobble; a facing flip needs |vx| > 0.2 px/tick and a 6-tick cooldown so it never dithers at the turn points; the turn tick holds position (2-frame flip: half-width old facing, then full new facing). Flakes override sleep so a night auto-feed is still eaten. Starving uses the `hungry` strip (no starving strip in the manifest).
- Flakes are stepped at 8 fps (they are entities the fish targets); leftovers settle on the gravel and dissolve after 30 s, which also emits `flakes-gone`.
- `loadTextures` is lenient: a missing PNG is logged and its layer/strip skipped (sprite falls back to transforms), so missing art never blocks the scene.
- `src/render/index.ts` pulls in pixi.js; `paintTrayChip`, `makeWaterBounds`, `parseManifest` are Pixi-free and importable from `./trayChip`, `./water`, `./manifest` under node.
- `night.png` is masked by the concept bowl's alpha (transparent wherever the bowl is transparent). Reason: a `multiply` sprite over a transparent RenderTexture pixel yields opaque black (`DST_COLOR * src + dst * (1 - srcA)` with `dst = 0`, alpha `ONE * srcA`), so an opaque-rect night layer painted black corners around the bowl at night. Verified by RT readback (`renderer.extract.pixels({ target: rt })`): water 50,155,217 → 14,51,128 under night, bowl-transparent pixels stay 0,0,0,0.
- Verification method for the scene (no Playwright yet): a throwaway harness (`src/render/__harness.*`, deleted before hand-off) mounted the real scene and drove `app.ticker.update(t)` synchronously in 16.7 ms steps, because the desktop Browser pane keeps the tab `document.hidden` (2 rAF frames per 3.7 s, and Pixi caps `deltaMS` at `Ticker.maxElapsedMS` = 100 ms), which starves the 8 fps accumulator and every timed fade. Readbacks, not screenshots, are the ground truth there: WebGL canvases in a hidden tab present stale frames. Checked this way: feed → 6 bites + `flakes-gone` within ~1 s of driven time; night fade in/out; starving posture on the gravel; pantry crop (`fraction 0.6` → frame y 11, h 9, Sprite re-measured) and the 500 ms 1.0/0.6 blink; asleep at the floor; dead (belly-up, fog) and memorial (empty bowl, flag, no fish); scale 2/3/4 and `habitatHitRect()`; tray chip at 36 px.
- `HabitatScene.setView` diffs `prev` against `next` by field, so callers must pass a fresh object per call (the store's immutable snapshots do). Mutating and re-passing the same object skips the change; the harness had that bug, the app cannot.
- Placeholder stamp rule (Blueprint section 12 "mark them PLACEHOLDER visibly"): every generated 160x120 layer carries the full word `PLACEHOLDER` (43x5 px in the generator's 3x5 font). The abbreviation `PH`, always in the magenta STAMP colour, is used only where the word cannot fit: the fish strips (the stamp must stay inside the 28x14 body box, see the orchestrator note below) and `pantry_fill` (opaque pixels must stay inside the 18x15 `pantryRect`, which now reads `PH` over `FILL`). `night.png`'s stamp moved from x 44 to x 56: the layer is masked by the concept bowl's alpha and the base is only opaque at x 52..110 on those rows, so the old stamp lost `PL`. `src/render/placeholderStamps.test.ts` decodes the checked-in PNGs and matches the glyph pattern colour-independently, so a clipped or missing stamp fails in CI.

### integration
- `src/main.ts` follows the contract's boot order literally: platform → store.boot → loadManifest/createScene/scene.mount(#app) → `#ui` div appended after the canvas → initAudio → HUD/dev panel/speech/pantry dialog/montage/memorial → wireTray/installKeys → subscriptions → pointer/moved/drag/contextmenu wiring → `platform.window.setScale` → `refreshHitRegions()` → `show()` unless hidden → scheduler + 60 s night tick → montage from `recentEvents` then a `wake` line. Boot runs inside try/catch; on failure the error is painted into `#app` as a `<pre id="boot-error">` and the window is still shown (the platform is created outside the try so the same instance is reused).
- `refreshHitRegions()` in main.ts is the only caller of `platform.window.setHitRegions`; it guards against the HUD/dev panel calling `requestHitRegions` while they are still mounting (both handles are `null` until `mountHud`/`mountDevPanel` return).
- The scene subscription only recomputes `toSceneView` when `pet`, `hunger`, `night` or `latches` changed by identity; `lastFeedEvent` identity change → `scene.feed()` + `audio.play('feed')` for both manual and auto feeds; `settings.scale` change → `scene.setScale`, `hud.relayout()`, `refreshHitRegions()` (the store awaits `platform.window.setScale` before committing, so the window is already resized when the subscriber runs).
- Pointer: `inside` → cancel the grace timer, `hud.setVisible(true)`, `scene.setPointer(x, y)`; `outside` → `scene.setPointer(null, null)` immediately and a single 400 ms grace timer before `hud.setVisible(false)`. Drag starts only from a left-button `mousedown` on the canvas element; `#ui` children stop propagation themselves. `contextmenu` on `#app` is prevented and routed to `platform.window.popupMenu()`.
- Tray "Mute" mutes audio only (Blueprint: "Mute in tray" is an audio control); speech bubbles are visual and stay on. `audio.setMuted` is applied once at boot and again by `wireTray` on every settings change. `alert` plays on a label transition into hungry/starving and `death` when the same pet turns dead; both are optional files.
- Render fix found in the smoke test: the pet sprite is now hidden until the first behavior step positions it (`placed` flag in `src/render/scene.ts`). Before, the pre-ticker render in `mount()` and the first ~125 ms of ticker frames (8 fps accumulator) drew the fish at grid (0, 0), which showed up as an orange blob in the top-left pad in a boot screenshot.
- Browser smoke test (Vite preview on 4173, desktop Browser pane): bowl renders with the fish inside the water, canvas backing store 1056×816 for 528×408 CSS (crisp at DPR 2), no console errors; hover → pill `100% Guppy #3857 FEED 25 MIN` and caption `PANTRY 0 $FEED · 0 DAYS`; FEED → flakes at the surface, fish rises and eats, `pet.json` balance 975 / meals 1 / feedBurned 25, pantry dialog reads `BALANCE 975 $FEED`; pointer out → HUD hidden after the grace; `size-l` → `#app` 688×528 and canvas 1376×1056; day override removes the night tint; `pendingSkipMs = 3 d` + reload → montage with "got hungry" / "started starving" lines, two toasts, pill 0 %, wake bubble after CONTINUE. The pane keeps the tab hidden, so animation timing (fish sinking to the gravel when starving, flake dissolve) was not observed at real frame rate. The mock `#mock-menu` is present in the DOM with 15 items after a right-click but the pane's screenshots do not composite it; not verified visually.
- Playwright (Blueprint section 12, "60-second recording"): `playwright.config.ts` runs `tests/e2e/**` against `vite preview` on 4173 (the built `dist/`, so `npm run build` precedes `npm run test:e2e`; `reuseExistingServer` lets a running preview be reused), one Chromium worker, viewport 528×408 (the M window), `video: 'on'`. `smoke.spec.ts` is the 1 s boot check; `acceptance.spec.ts` walks Blueprint section 11 in browser mode through the real UI (hover HUD, FEED 25, dev panel via Alt+Meta+D, Meta+Equal/Minus) and uses `window.__webpetsMock` only for what Rust owns under Tauri (`reset()`, `emitToggleVisibility()`, `notifications`). Facts the script relies on: hungry at 48 h (+12H×4, hunger 20 %), starving at 60 h, dead after +3D more; "fed" speech line = the scene's `bite`, so it doubles as the "flakes fell and the fish ate" assertion; the 10-day/500-pantry dry run prints exactly 8 `ate from the pantry` lines and the live skip (+3D×3, +12H×2) leaves pantry 300 (caption `PANTRY 300 $FEED · 13 DAYS`); "Skip 3d on next launch" + `page.reload()` plays a montage with 3 pantry meals (pantry 225, hunger 75 %) and the dev clock offset is cumulative (`+18d 12h` by then). The run is ~28 s of video; pauses are `BEAT_MS` beats, not padding to a literal minute. `gotoFresh` waits 700 ms before `reset()` so boot's throttled pet save cannot resurrect the old pet on the reload.

### orchestrator (runtime verification)
- The main window is `set_visible_on_all_workspaces(true)`: a corner pet belongs on every Space, and on macOS that collection behavior also keeps Stage Manager (enabled on Sammy's Mac) from treating it as an app window.
- Dev-only diagnostics bridge: `tools/vite-diag-plugin.ts` + `src/dev/diag.ts`. `curl 'http://localhost:1420/__webpets/snap?name=x'` asks every connected frontend (the `tauri dev` webview and any browser tab) to POST a PNG of the canvas plus a state dump into `.diag/` (gitignored). - Lock-screen note for anyone reading the window server: while the screen is locked macOS scales every window's reported bounds by 0.9 about the display center (528×408 at (960,471) reads as 476×368 at (939,473)); the geometry code is correct.
- The WKWebView is suspended by WebKit while the display sleeps/locks, so the frontend's 30 s ticks stop; the Rust `wake` event and the boot reconcile cover the gap (observed: a 16 minute sleep was reconciled on wake).
- First-launch restore prefers `positions.last` (the monitor the habitat was on when its position was last persisted) over the monitor the hidden window currently reports. Before this, `set_scale`'s first call restored the first candidate with any entry, and the candidate list always began with the hidden, config-placed window's monitor (the primary), so on multi-monitor setups a stale primary entry beat the external display the user had dragged to. `last` lives inside `positions` (not a sibling key) so Rust still owns exactly one top-level key; monitor keys always contain `@`, so `last` cannot collide. `pick_restore` is pure and unit-tested.
- Placeholder fish strips: the magenta `PH` stamp is drawn inside the 28x14 `body` box centred in each 80x80 frame (7x5 px over the middle of the body), not in the frame corner. Behavior only keeps the body box inside the water and the sprite uses anchor 0.5, so a corner stamp was composited ~30 px up-left of the fish, on the bowl rim or in the transparent pad (and duplicated in the shadow copies). `check_stamp_in_body` in `tools/gen_placeholders.py` asserts it at generation time and `src/render/spriteStrips.test.ts` decodes the checked-in PNGs and asserts it against the manifest.
- Dead-phase fog is masked to the water band: the manifest ellipse (cy 58, ry 42) reaches y 16..100 while the water is 23..96, so an unmasked fog also painted 7 rows of rim/air gap above the surface and 4 rows of gravel below the floor. `src/render/layers.ts` now masks the fog Graphics with a `makeWaterBounds(waterShape).rect` rect (a child of the fog, so it shares visibility and the glass-slot parallax), matching how the fish clamp, bubbles and flakes are bounded.
- `PersistApi` is split into `set(file, data)` and `save(file)`. The old single `save(file, data)` did the plugin's `store.set('doc')` and `store.save()` together, and `src/app/persistence.ts` throttled that whole call, so during a 500 ms burst the store plugin's in-memory document lagged the app by up to 500 ms; the plugin's `RunEvent::Exit` safety-save (logout, crash, Force Quit, anything but tray Quit/hide/beforeunload, which `flush()` first) then wrote the pre-change document. Now every channel save enqueues `set` at once and only `save` is throttled; both go through one per-file promise chain so a trailing `save` always follows the latest `set`. The fake platform models the two layers separately (`cache` = plugin memory, `files` = disk) and `persistence.test.ts` asserts `setCount` vs `saveCount`.
- Modal `.line` rows wrap (`white-space: normal; overflow-wrap: anywhere; line-height: 10px`) instead of `nowrap`. Press Start 2P advances 8 px per glyph, so the old pantry hint (34 chars = 272 px) overflowed the widest card (240 px, 226 inner) at every scale and the BALANCE/PANTRY lines (26+ chars) overflowed the 160 px card at S, spilling past the border and drop shadow. The hint is now `PANTRY_HINT` = `Auto-feeds 25 at hunger 30` (26 chars, one line at M/L, two at S); `src/ui/pantryDialog.test.ts` asserts the hint fits `CARD_MAX_INNER_WIDTH` and that the stylesheet keeps `.modal .line` wrapping. The card width formula is unchanged, so it stays inside `habitatHitRect` and no hit region changes.
- Dev panel shortcut: the Blueprint's ⌥⌘D is also macOS's system shortcut for "Turn Dock Hiding On/Off", which the system consumes before the webview sees it. The binding stays as specified; `commandFor` ignores Shift, so ⇧⌥⌘D already toggles the same panel, and the tray menu's "Dev panel" item is the third path. Documented in the README rather than rebound, because the Blueprint names the chord.

### stage 0
- The habitat grid, the window padding and the scale ladder are now single-sourced. `windowSizeForScale(scale)` lives in `src/sim/constants.ts` next to `GRID_W`/`GRID_H`/`WINDOW_PAD`/`SCALES`; `src/platform/geometry.ts` re-exports it (so `src/platform/browser.ts` and `geometry.test.ts` keep importing it from there) and `src/render/scene.ts`'s `windowSize` is a `{ w, h }` wrapper around it. sim is the only place all three modules may share: the contract lets `render` import `sim` but not `platform`, so the helper cannot live in `src/platform/geometry.ts` where it used to be duplicated.
- The RenderTexture in `src/render/scene.ts` is now sized from the manifest's `habitat.grid` instead of the constants, so the texture dimensions flow from data. The existing equality check stays and its message now says why: the window geometry around the texture is still derived from the constants, so a manifest with a different grid would be drawn into a texture the window has no room for. `parallaxOffset` in `src/render/fx.ts` takes the grid and measures from its centre instead of hardcoding `(80, 60)`, the same way `createBubbles`/`createSheen` take their geometry from the manifest's `waterShape`.
- Rust cannot import any of that, so `src-tauri/src/window.rs` keeps its own constants and a `contract_sync` test module pins them to the TypeScript: `include_str!("../../src/sim/constants.ts")` plus a small string scan for `export const <name> = <value>;` (tolerant of whitespace, type annotations, comments and a trailing comma, and it panics with a "the parser stopped matching" message rather than passing vacuously), `include_str!("../tauri.conf.json")` parsed with serde_json. It asserts Rust's `GRID_W`/`GRID_H`/`WINDOW_PAD` equal the TS ones, that the range `set_scale` accepts equals the TS `SCALES` list (extracted as `MIN_SCALE`/`MAX_SCALE` + `scale_supported`, and the list must stay a contiguous run for a range to express it), and that the `tauri.conf.json` fallback window equals `window_size_for_scale(<middle of SCALES>)`. Every message names the file and the value to change, because a later stage will change these numbers and this test is what catches a half-finished change.
- Why a test and not generated code: a build script emitting Rust from the TS (or a shared `geometry.json` both sides read) would make the numbers literally single-sourced, but `src/sim/purity.test.ts` forbids anything in `src/sim` importing outside itself, so the TS side could not read a shared JSON file without either breaking purity or adding a codegen step that writes `constants.ts` — and a generated file is worse to read and review than the one-line constants it replaces. A test costs nothing at runtime, keeps both files hand-written and fails the build (`cargo test`) the moment they disagree, which is the actual requirement.
- No behaviour or visual change in this stage: grid 160×120, pad 24 and scales 2/3/4 are byte-identical, and all 162 Vitest tests, both Playwright specs and the 12 pre-existing Rust tests passed untouched (the Rust count is now 15). Drift was verified by temporarily setting `GRID_W = 192` / `SCALES = [2,3,4,5]` in the TS and watching all three new assertions fail with their fix instructions.
- Stage 0 follow-up, from the adversarial review of the new guard: `ts_initializer` scanned the raw text of `constants.ts`, so a commented-out stale declaration could shadow the live one and silently defeat every assertion. It now strips `//` and `/* */` comments first (verified: decoy declarations in both comment styles are ignored, and real drift still fails with its fix instructions). The guard also only ran under `cargo test`, while the drift it catches is nearly always introduced from the TypeScript side; `tests/unit/contract-sync.test.ts` mirrors the same three assertions in Vitest so `npm test` fails immediately too. Both halves read the same three files, so they cannot disagree about the truth.
- The dev diagnostics bridge now polls as well as listening for the Vite HMR push. The Tauri webview reliably answers after an HMR-triggered reload but not on a fresh page load, while a browser tab answers either way; a 1 s poll of `/__webpets/poll` makes captures deterministic in both. Both delivery paths can fire for one request, so the client de-duplicates on the resolved file name.
- Browser-mode captures are a valid stand-in for the Tauri webview when checking what is rendered. Measured at the same scale, the two differ by 1.1% of pixels confined to grid x70..98, y58..90 — entirely inside the water, i.e. the animated fish at a different frame. Everything else (bowl, stand, gravel, plants, feeder) is pixel-identical, and the reported hit regions match exactly.

### stage 1 (render / art)
- The habitat grid is 320×240 and the fish frame 160×160, but **the rendered image is unchanged**: every checked-in PNG is an exact 2× NEAREST upscale of the 160×120/80×80 one (verified two ways — every 2×2 block is a single colour, and downsampling by 2 reproduces the previous file's bytes), and every geometry number in `assets/manifest.json` and `src/species/fish/layout.ts` is exactly doubled. So the app at the new scale 1 is pixel-identical to the old app at scale 2, and new scale 2 to old scale 4. Real 320×240 art is the next stage; separating them means a visual regression can only come from one of the two changes.
- `tools/gen_placeholders.py` is resolution-driven: grid, `waterShape`, `pantryRect`, `opaqueRect`, sprite `frame` and `body` all come from `assets/manifest.json` (with `--grid`/`--frame` overrides). Hand-placed coordinates stay written in the 160-wide art units the layout was authored in and go through `u(n)`. `FEEDER_BOX` is the one rect the manifest does not carry and is derived as `pantryRect` inflated by `u(1)`, so it cannot drift.
- How the generator produces a provable 2× upscale without a second code path: `--upscale N` (default `int(GRID_W / 160)`) draws each layer at `grid / N` and NEAREST-upscales by `N`, asserting the round-trip. At the default the drawing happens at exactly the old size with `u()` as the identity, so the output *is* the old art scaled up. `--upscale 1` draws natively at the full grid with `u(n) = round(n × 2)` and the stamp font at scale 2 — that is the Stage 2 path, and it was exercised to confirm it runs and passes the generation-time asserts.
- `bg` moved to `assets/habitats/fish/bowl/bg.png` (written by the new `tools/gen_bg.py`), so the manifest no longer encodes a resolution in a directory name. `assets/habitats-160x120/fish-bowl.png` stays as the source concept art. Stage 2 replaces the body of `gen_bg.py` with a real downscale from the 1168×880 reference; the path, the size assertion and the manifest entry do not move again.
- Every pixel constant in the motion code doubled with the grid, because a distance left at its old value is a half-speed fish in a bowl twice the size: `src/species/fish/behavior.ts` (bite range, turn threshold, dart speeds, step caps, wobble, floor/surface offsets, drift, the sub-pixel clamp tolerance), `src/render/food.ts` (flake spawn band, sink speed, drift, settle row) and `src/render/fx.ts` (bubble spawn row, speed, wobble, parallax clamp ±2 → ±4). Quantities that are *not* distances did not change: tick counts (`EAT_TICKS`, `TURN_COOLDOWN`, `WOBBLE_EVERY`, `DISSOLVE_STEPS`), `WANDER_RATE` (an angular rate), `FLAKES_PER_FEED`, and the parallax divisors (the offset from centre already doubles with the grid, so the clamp is the only thing that moves).
- Two pixel constants outside the brief's list would have silently changed the image and were caught by working through what "identical at half the scale" implies. (1) The drop shadow in `src/render/scene.ts` is offset by 1 and 2 **grid** px and drawn in CSS px as `offset × scale`; left alone it would have halved on screen. It is now `SHADOW_NEAR_PX`/`SHADOW_FAR_PX` = `1/2 × ART_UNIT`. (2) `src/render/spritePlayer.ts`'s transform fallback used literal 1–2 px bobs; they now scale off the manifest frame height. That path is unreachable while every fish state has a strip, but it is the same latent half-scale bug.
- The small FX pixel patterns (3×3 bubble, 4×10 sheen, 2×2 flake) are not redrawn at the new size. They stay authored on the 160 art grid and are nearest-upscaled by `ART_UNIT` (`GRID_W / 160`) in `src/render/fx.ts`, which is both readable and provably the same texture — the same trick the generator uses, for the same reason.
- `findWord` in `src/render/placeholderStamps.test.ts` now takes the stamp scale (`grid width / 160`) and checks every image pixel of each scaled font pixel. Without it the test would have found nothing at a 2× stamp and failed in a way that invites deleting the assertion; with it, a stamp drawn at the wrong scale still fails. Verified by forcing `scale = 1`: all 13 cases fail.
- `manifest.water.h` is **148**, not the 146 the stage brief listed. 148 is the exact double of the old 74 (the water's inclusive bounding rect); 146 is `floorY - surfaceY`, which is a different quantity — the half-open band `makeWaterBounds().rect` computes and `src/render/water.test.ts` asserts. Both are now consistent with the doubling rule. `opaqueRect` stays one art unit (now 2 grid px) wider and taller than the bg's measured alpha bbox, exactly as it was at 160×120; the hit region is a deliberate superset.

### stage 2 (real 320x240 art)
- `tools/gen_bg.py` no longer upscales the old art; it derives `assets/habitats/fish/bowl/bg.png` from `assets/reference/habitats-hires/fish-bowl.png` (1168×880). Pipeline: centre-crop to 1168×876 for the 4:3 grid aspect (the alternative was a silent 0.46% horizontal stretch), LANCZOS downscale on **premultiplied** RGBA at 3.65×, alpha thresholded to 0/255 with a despeckle pass, quantize to the 38 opaque colours of `assets/habitats-160x120/fish-bowl.png` with `dither=NONE`, then a 1px outline pass on the alpha boundary. Result: the gravel's individual pebbles, the wood grain on the stand and a 1px bowl rim are all legible where the Stage 1 upscale had 2×2 mush.
- The palette is the art's identity, so the new image is quantized to the *shipped* palette rather than to some fresh N-colour median cut. That is what makes this "the same art with more detail" instead of a different-looking picture, and it is why `src/render/bgArt.test.ts` asserts the colour set is a subset of those 38.
- `dither=NONE`, checked by eye against `--dither fs`: Floyd–Steinberg scatters single-pixel speckle across the flat water and the stand that reads as JPEG noise. Flat banding reads as deliberate. The flag stays so the call can be re-made.
- The outline pass **darkens** each boundary pixel and re-snaps it to the palette rather than painting one global darkest colour (`--outline darkest`). Measured first: the shipped 160×120 art already has a dark outline on all 424 of its silhouette pixels (median luminance 25, max 105) and it is *contextual* — dark navy on the glass, dark brown on the stand. A uniform black outline reads as a sticker; side-by-side crops at 8× made that obvious. `--outline none` reads as a cut-out photograph, which is exactly the failure mode this stage was warned about.
- **Stage 1's geometry numbers were not just stale, they were unreachable.** They were the 160×120 values doubled, and no threshold, crop or resample of the current hi-res reference reproduces that silhouette: the shipped 160×120 art is ~3.4% wider and ~3.1% taller than any downscale of it, anchored at the top-left (its bowl reaches x122 of 160 where every downscale reaches x119–120). So the shipped art is not a pure downscale of this reference file — it came from an earlier or differently-scaled render. That one fact explains all three disagreements larger than 2px: `opaqueRect` (w168→162, h230→224), `pantryRect.x` (186→180) and `waterShape.cx` (162→160). The art on disk is the source of truth and every number was re-measured from it.
- `waterShape` is a least-squares ellipse fit to the measured water rows (rms 0.58px over 147 rows) rather than a hand-tuned guess. Half-widths are median-smoothed over five rows first: a single bright glass highlight fails the water predicate and pinches one row by 8px, and an unsmoothed containment pass shrank `rx` from 78.7 to 75.5 chasing that artifact. Checked afterwards: sampling the fitted ellipse's edge on every row lands on an opaque pixel 100% of the time, so the swim area never leaves the drawn bowl.
- `surfaceY` is 44, the bowl's topmost opaque row — **not** the painted meniscus at ~y75. That is what Phase 0 measured and what behaviour depends on (the fish may drift up into the air gap above the water line). Stage 2 re-measured it; changing the semantic is a behaviour decision for another stage.
- `pantryRect` is found structurally: flood the non-housing pixels inward from the border of the region above the water, and whatever is left unreached is enclosed by the feeder's dark housing. Detecting it by flake colour does not work — the gravel is the same orange, and the flakes falling below the feeder stretch the box down into the water. Cross-checked by running the same detector on the shipped 160×120 art, where it recovers x92 y7 w18 h14 against the authored x93 y5 w18 h15.
- `opaqueRect` now equals the bg's alpha bbox **exactly**, dropping the Stage 1 convention of a deliberate one-art-unit superset. `habitatHitRect()` is `pad + opaqueRect × scale`, so slack there means the transparent pad is clickable and the always-on-top window steals clicks from whatever is behind it. `src/render/bgArt.test.ts` pins it; that test is the click-through regression guard.
- `tools/gen_fish.py` is new and the fish strips are real art. The goldfish painted into the concept render is segmented out (flood the water in from the border of a fixed crop, keep the largest non-water island — a plain bbox crop keeps the water, bubbles and plant), downscaled to 64×48, and every animation frame is a *transform of that one image*: a travelling-wave column shear for the tail, a column shear for the lean, a per-column vertical resample for the fin droop, a wedge cut at the snout for the gape, a lid line over the pupil for the blink, a flip plus desaturation for `dead`. So the fish is recognisably the same fish in every pose, and there is no second hand-drawn asset to keep in sync.
- The sprite uses the **warm half** of the bowl palette (10 entries with `b <= r`) plus its near-white — eleven colours, all the bowl's own. Quantizing the isolated fish against all 38 speckles the pale fin highlights with teal, because most of the palette is water blue and the painted fish's own colours are seen *through* that water. `dead` is the exception: desaturated first, then quantized against the full palette, which is where the greys live.
- The fin droop was first written as copy-the-pixel-down, which tore a transparent seam straight across the body at the row where the shift first reached 1. It is now a monotone per-column resample (`out[y] = src[y - shift(y)]`), which duplicates instead of tearing. Caught by looking at the frames, not by a test.
- `body` is **56×46**, not the 56×28 that doubling Stage 1 suggests. The drawn fish is 64×48, and the box has to be smaller than the art so fins may overlap the glass — but only just, vertically. Because `surfaceY` is the bowl's topmost opaque row, the clamp puts the box's top edge flush with the glass at the top of the swim range, so every px the box is shorter than the art is a px of dorsal fin hanging outside the bowl in the transparent pad. Measured: `h=40` leaves up to 50 stray pixels (a visibly detached fin at size L), `h=44` leaves 30, `h=46` leaves 6–14 — a 3px sliver that reads as the fin touching the rim — and `h=48` would exceed the drawn height of `curious`. 46 is the largest value that is still smaller than every frame's art.
- `happy`, `excited` and `curious` strips and `assets/sprites/fish/emotes.png` ship now although nothing plays them. `PetAnim` is a closed union that does not name them and the sprite player only looks up the state it is asked for, so the manifest entries are inert; generating them now avoids a second art pass in Stage 4. `src/render/manifest.test.ts` names all eight so the extra three cannot arrive unnoticed.
- The `zzz` emote is drawn as bare 5×5 Z strokes with no fill. At that size an outline-plus-fill Z is a blob and the diagonal — the only thing that makes it a Z — disappears. Verified by rendering the strip over both the mid-blue water and the pale upper glass.
- `tools/gen_placeholders.py` now defaults to `--upscale 1` (draw natively at the full grid) and no longer generates the fish strips at all; `--upscale 2` is kept because it is the only way to re-verify Stage 1's "provably the old art scaled up" claim. The `night` layer's stamp position is now *searched for* (`stamp_spot`) instead of hardcoded: that layer is clipped to the bowl's alpha, and the new, slightly smaller silhouette pushed the old hand-placed stamp onto transparent pixels, where `placeholderStamps.test.ts` correctly stopped finding the word. Searching the mask means new background art cannot silently erase a stamp.
- The stamp contract is now two-sided, which is why the tests were updated rather than deleted: the synthetic layers must carry the word, and the real art must carry **no** stamp pixel at all (`placeholderStamps.test.ts`). `spriteStrips.test.ts` stopped asserting "stamp pixels inside the body box" — which no longer has anything to assert — and now asserts the layout contract that replaced it: one horizontal row of frame-sized cells, art in every frame, art centred in its cell, and art strictly larger than the `body` box but by no more than 12px a side.
- Known cosmetic issue, pre-existing and unchanged: the `pantry` layer's PLACEHOLDER stamp is drawn to the right of the feeder, outside `opaqueRect`, so it floats in the transparent pad next to the bowl. It was outside at 160×120 too (the word is 86px wide and there is nowhere inside the bowl's top-right to put it). It disappears when real feeder art lands.

### stage 2 (integration verification and fixes)
Four defects were found after the art landed, three of them by looking at the running app rather than by reading the diff.

- **The dead fish rendered outside the bowl.** `behavior.ts`'s dead branch called `bounds.clamp(...)` and then threw away the clamped `y`, writing the raw `surfaceY + 12` instead. `surfaceY` is the topmost water row, so the body's centre sat above the legal band and roughly a sixth of the goldfish hung through the glass. Worse, the existing test *encoded* the bug: it asserted the raw value and checked only `bounds.inside(centre)`, which is true while the fins are outside. The test now asserts the clamped position and checks all four corners of the body box.
- **Settled flakes had become uneatable.** Raising `body.h` from 28 to 46 (needed so the dorsal fin stays inside the glass) also stopped the body's *centre* from reaching the gravel: deepest reachable centre y=167, flakes settle at y=186, bite range 12. The fish would hover over its dinner until the flake dissolved 30 s later. Fixed by measuring bite distance from the body BOX rather than its centre, which is what "the fish can reach it" physically means — a fish eats with its mouth, on its outline, not with a point at its middle. This is the same finding that was raised and correctly refuted in Phase 0, when the smaller body made it false.
- **Two strips animated as stills.** `sleep` and `curious` used a wag phase of `i / 8` across only 4 frames, spanning a quarter cycle, so adjacent frames rounded to identical pixels: `sleep` frames 0 and 1 were byte-identical. Every healthy state spans a full cycle (`i / frames`). `spriteStrips.test.ts` now asserts consecutive frames differ by at least 2% of the fish, which catches the whole class — a strip can pass every other check and still render as a still image.
- **Placeholder layers were covering the real art.** Once `bg` became real art, the labelled stand-ins drawn on top of it hid the very thing they stood in for: `medium` alone painted a pale tinted ellipse with magenta text over a quarter of the frame, washing out the new water, gravel and plants. The purely decorative slots (`decor_back`, `decor_front`, `glass`) are now empty, and `medium`/`pantry` draw only their functional pixels — the patches that hide the fish and the flakes painted into the concept art, so the live sprite and the real pantry gauge are the only ones visible. `gen_placeholders.py --labeled` restores the old content for debugging the layer stack, and the stamp test now asserts which layers are empty, which are functional-only and which are still stamped.
- **The heal patch took three attempts** and is worth recording because the first two looked plausible: filling each row with one flat colour left a pale rectangle sitting on dithered water, and tiling a run of neighbouring water dragged the bowl's specular streak across the patch as ghost blobs. Taking the median per dither phase over a wide window on the same row reproduces the pattern while outliers like the highlight are voted out. The painted fish is now found by flood-filling the largest orange blob, because the real art has orange in the plant fronds and the falling flakes and a bounding box around every orange pixel swallowed half the bowl.

Tooling, because the captures are the only eyes available here:
- `HabitatScene.debugState()` reports what the scene is actually drawing (pet visibility, position, frame, per-slot alpha) into the diagnostics dump. "The fish is missing" took far longer to diagnose than it should have without it.
- `snapshot()` now steps the behaviour once if it never has. A hidden tab gets no ticker callbacks, the pet sprite stays hidden at (0,0) until its first step places it, and a capture of a backgrounded page therefore showed an empty bowl that looked exactly like a rendering bug.
- Verified after the fixes: pixel alignment PASS at scale 1 (0 violations across 79,056 blocks), 231 unit tests, 16 Rust tests, both e2e specs, clippy clean.

### release bundle: the habitat rendered nothing
The packaged `.app` showed the HUD pill and the caption but a completely empty habitat, while `npm run tauri dev` rendered correctly the whole time. Two independent bugs, neither reachable from the dev server, and a first diagnosis that was wrong.

**Bug 1: every texture failed to load, because Pixi's URL helper is blind to custom schemes.** `path.rootname('tauri://localhost/index.html')` returns `'tauri://'` — the host is dropped, because `isUrl()` only recognises http and https. Joining that root with our `/sprites/fish/idle.png` produced `tauri://sprites/fish/idle.png`, a request that reaches the protocol handler with "sprites" as the host, returns something that is not a PNG, and fails in `createImageBitmap` with "Cannot decode the data". Reproduced directly: `path.rootname` and `path.join` from the installed package yield exactly the URL from the error.
  - *Fix:* `assetUrl()` now resolves against `document.baseURI` with the WHATWG parser, which keeps the host, and `loadTexture` fetches the blob and builds the `ImageSource`/`Texture` itself instead of going through `Assets.load`, so Pixi never gets the chance to rewrite the URL. The `ImageSource` options mirror Pixi's own loader, `premultiply-alpha-on-upload` included, or transparent edges go wrong.
  - *Also changed, as hardening rather than the cause:* Pixi's default is to load textures inside a Web Worker created from a `blob:` URL. That worker's `fetch` is a second way this breaks under a custom scheme, so `preferWorkers` is off. `preferCreateImageBitmap` is deliberately left on: the other path hard-sets `crossOrigin="anonymous"` on an `HTMLImageElement`, and a `tauri://` response carries no `Access-Control-Allow-Origin`, so disabling it would trade one bug for a real CORS failure.
  - *My first diagnosis blamed the worker alone.* It was a real hazard but not what was breaking: with workers disabled the failure simply moved from silence to a decode error, which is what finally named the URL.

**Bug 2: the scene was frozen, because `requestAnimationFrame` never fired.** The window is created hidden and shown only once boot finishes, so WebKit loads the page in the hidden visibility state and throttles rAF to nothing — and does not necessarily resume when the window appears. Measured in a real build: the ticker callback had run **zero** times a second after boot. Pixi's `ticker.FPS` reported 60 throughout, which is worse than no signal: that value is seeded to 60 and only corrected by a tick that never came.
  - *Fix:* a watchdog drives the same `advance()` from a `setInterval` whenever rAF has been quiet for 400 ms, at the pet's own 8 fps. When rAF is healthy it sees a recent advance and does nothing. A pet whose clock never pauses should not have its animation depend on the compositor's opinion of whether anyone is looking.
  - *Second fix in the same area:* the pet sprite used to start invisible at (0,0) and was shown by the first behaviour step, so a frozen ticker meant a bowl with no fish in it. It is now placed at its anchor through the player's API at mount. Setting `sprite.position` directly does not survive, because the player re-derives it from its own `px/py` inside `refresh()`.

**Why nothing caught either one.** Our `loadTextures` defaulted to lenient, turning a total asset outage into a `console.warn` and a mounted, correctly sized, fully transparent scene. Leniency is now scoped: the background and the pet's idle strip are required and throw, so `main.ts` paints its visible error box; everything else stays optional. And no test in this repo can reach this class of bug — Playwright drives `vite preview` over `http://`, which is exactly the scheme that works.

**Standing rule: every stage from here must be verified in a built `.app`, not just under `tauri dev`.** This matters immediately for the atmosphere work, since filters and particle containers lean on the same worker and blob machinery. Related: `csp` is currently `null`; if a CSP is ever added it needs `worker-src blob:` or this breaks a second way.

**Release builds now write `boot-report.json`** next to `pet.json`, through the existing store so there is no new command or permission. It records the canvas size, the error and stack when boot fails, and the scene's state including a behaviour-step counter and whether a view was ever applied. It is written on both the success and the failure path and delayed a second so it samples a settled scene. A packaged app has no devtools and this machine has no screen-recording permission; without this file a release build is completely opaque, and it is what turned "the bowl is empty" into an exact URL and a step count of zero.

### the fish swam above the waterline, and the feeder was a black box
Two visual complaints from running the beta, both traced to the same root: geometry measured off someone else's painting by a tool that could not tell water from glass.

- **`surfaceY` meant the top of the glass, not the top of the water.** It was 44, the bowl's inner rim; the painted waterline is at 80. The fish could therefore drift a quarter of the bowl up into the empty air pocket and read as floating outside the tank. The bad number came from `gen_bg.py`: its `is_water` test accepted the pale blue of the air pocket seen through glass, and the row it settled on had exactly two qualifying pixels, **both inside the feeder rather than the bowl**. Fixed at the source as well as in the data — the predicate now gates on saturation (water ~0.70 vs air ~0.46-0.55) and value (to reject the dark navy rim), and the tool's own report and the manifest now agree to the pixel, which is the thing whose absence caused this.
- **A latent bug the fix exposed.** `wanderTarget` subtracted the body half-height from a band the callers had already inset by it. With the old full-glass band that merely flattened the figure-eight; with the real waterline the band is short enough that the double inset collapsed the vertical sweep to its 4px floor and the fish swam a dead straight line. Removing the second inset takes the sweep from 6.8 to 28.4 and improves the old behaviour too.
- **`petAnchor` was the centre of the glass**, not of the water, so the pet mounted above the surface. Now the water centre, and `layout.test.ts` derives it rather than hardcoding a literal — a literal is exactly what went stale here.
- **The feeder is gone.** Two layers drew it: the concept art paints a detailed one onto the rim, and `pantry.png` then covered it with a flat `#262A34` slab, which is what read as a big black square. Erasing it is geometric rather than a hand-typed rectangle — the feeder and its clip are the only opaque pixels in the top-right quadrant lying **outside the bowl's own outer glass ellipse** (fitted from the art at cx 160, cy 116, rx 81, ry 72), which a literal box cannot express because the clip crosses the rim. The flakes painted falling from its spout go too, but only above the waterline: the plant below has orange fronds that must survive.
- **Consequences, all verified.** `opaqueRect` shrinks to `{79, 44, 162, 188}` — the feeder housing used to be the topmost opaque thing in the art, so the click-through region was reaching well above the bowl. `pantryRect` and the `pantry`/`pantry_fill` layers are removed and `ManifestHabitat.pantryRect` is now optional, because a habitat need not carry an in-scene food gauge. The pantry level reads in the hover caption instead, which **deviates from the Blueprint's visible away-mode gauge** (section 6, item 4) at the user's explicit direction. Gravel reach is unaffected: the lowest legal body centre stays at 167 and bite distance is measured from the body box, so the settled-flake regression test passes untouched.

### stage 2 (render): pixel-perfect out, smooth out of the same coordinates
The art direction reversed — cozy pixel art out, soft 3D in — at the user's explicit direction, after
running the beta. This is the render half of that. The rule that made it cheap: **the 320x240 grid stays
as LOGICAL coordinates and only its presentation changes.** Behaviour, water bounds, hit regions, the
manifest geometry and every test that reasons in grid units survive untouched.

- **The RenderTexture is gone.** Compositing into a 320x240 texture at resolution 1 and upscaling it
  nearest existed for exactly one reason: to guarantee big square pixels. `layers.root` now draws
  straight to the stage, carrying the window scale, while each file-backed layer carries the reciprocal
  of its own art resolution. One transform chain, three places, none of them in the middle.
- **Art resolution is DERIVED from the texture, never declared.** `layerArtScale()` computes
  `texture.width / grid.w` and throws by name if it is not a whole number or the axes disagree. A
  manifest field would have been one more thing to drift; deriving it also lets a 1x pixel layer and a
  4x rendered one coexist while art is migrated one layer at a time, which is what made this landable
  in a state where the tests still pass.
- **The drop shadow went with the RenderTexture**, being two black-tinted copies of it. Tinting the
  layer root instead is not equivalent — it would black out the multiply night layer and the white fog.
  The 3D bowl art carries a baked contact shadow, and a stepped offset shadow on top of a baked one
  reads as a bug.
- **Three clocks, not one.** `PET_FPS` drove both the simulation and the animation. Raising it to 30 to
  get smooth motion, which is what the plan originally said, would have rescaled every per-tick constant
  in `behavior.ts` — px/tick speeds, `TURN_COOLDOWN`, `WANDER_RATE`, `EAT_TICKS` — and invalidated their
  tests. Instead the behaviour still ticks at 8 Hz and still returns clamped integer positions; the
  animation advances at the art's own fps (`ManifestSprite.fps`); and the drawn position is interpolated
  across the current tick on every rendered frame. Interpolation is derived from the SAME accumulator
  that drives the steps, so the two cannot drift.
- **Interpolating between two clamped positions is provably legal**, not merely close enough: the legal
  set for a body centre is the water ellipse eroded by the body box and cut to the surface/floor band.
  Erosion of a convex set is convex and intersections of convex sets are convex, so every point on the
  segment between two legal centres is legal.
- **Turning is a cosine sweep of `scale.x` through zero**, which is what a half-turn about the fish's
  vertical axis actually projects to under an orthographic camera — the correct 3D reading of the
  pixel-art device of drawing one frame at half width. It is keyed off the facing CHANGE rather than the
  behaviour's one-tick `turning` pulse, because several rendered frames now share one tick and a pulse
  can be missed or re-applied.
- **Frames may be a strip or a sequence of files**, and the new art will be sequences. Not only because
  that is what a renderer emits: a strip **cannot be mipmapped**, since neighbouring frames bleed into
  each other at low mip levels. Mipmaps are mandatory here — at the smallest window the art is minified
  4:1 or worse, and bilinear-only minification of a large texture crawls as the sprite moves, which is
  the exact artefact smooth art is supposed to remove.
- **`image-rendering: pixelated` is off the habitat canvas.** It is outside Pixi's control: the browser
  scales the backing store to CSS px, so at a fractional device pixel ratio it re-introduces hard
  stair-steps no matter how the textures are filtered. The `#ui canvas` rule stays, because the tray
  chip really is pixel art.
- **Two things now have guards that never existed.** Nothing asserted the filter mode, so the entire
  smooth switch could have been silently undone by one word; and nothing could see the clock split.
  `assets.test.ts` pins `linear`, and `spritePlayer.test.ts` pins fractional positions, the art-scale
  invariance, the turn sweep and the art-rate frame clock. All four were verified by mutation — each
  fails on the obvious regression.
- **Checkpoint deliberately taken with the OLD art still in place**, so that the clock and transform
  work is proven green before any pixel changes. A later regression is then unambiguously about the art.
  Verified: 244 unit tests, both Playwright specs, and a captured frame showing the bowl, fish, plant
  and bubbles drawing correctly through the new path with no console errors.

### stage 2 (fx): the last pixel art in the renderer
Bubbles, food flakes and the pointer sheen were hand-authored RGBA byte patterns on the retired 160x120
art grid — a 3x3 bubble ring, a 2x2 flake, a 4x10 sheen — nearest-upscaled by `ART_UNIT` to fit the
320x240 grid. That worked only because the WHOLE frame was uniformly upscaled; drawn over smooth art at
the largest window, a flake was a 24 device-px hard-edged brown square.

- They are now generated procedurally at `FX_SS` (8) texture px per grid px and drawn back down, with
  every edge built from a smoothstep rather than a cutoff. The bubble is a bright rim with a nearly
  clear middle and one highlight, which is what reads as a bubble rather than a dot; the flake is an
  irregular soft crumb, lit from the top-left to match the habitat's key light, with a cheap angular
  radius wobble so six flakes are not six identical discs.
- **Sprites are anchored 0.5 and scaled by 1/FX_SS**, so all three are positioned by their CENTRE in
  grid px — which is what the physics already computed. The old code offset each by half its texture
  size at every call site instead.
- `ART_UNIT` and `upscalePattern` are gone. `ART_UNIT` was the renderer's last dependency on the
  160x120 grid retired two stages ago.
- **Three things stopped rounding to whole grid px**: flake draw positions, the pointer sheen, and the
  parallax offset. Each was correct when a grid px was the smallest thing that could move. The parallax
  one was the most visible — a continuous slide delivered as a four-step stagger.

### the mood engine: feelings without a model
The original ask was a pet that feels alive and has feelings, with "ai integrated". Resolved with the
user to: no API, no network, no cost, built in. `src/sim/mood.ts` is the result — pure, deterministic,
no clock and no RNG, so the same inputs always give the same mood.

- **Valence and arousal, not an enum.** The circumplex model, because the interesting states are the
  ones a flat enum cannot express: low valence with HIGH arousal is agitation, low valence with LOW
  arousal is misery, and a pet should not play them the same way. Labels are read off the plane at the
  end rather than tracked.
- **Hunger's effect on arousal is deliberately not monotonic.** Hunger is agitating until it is
  exhausting: arousal peaks around a fifth of the bar, where the animal is hunting, and collapses at
  zero, where it has given up. A monotonic version makes a pet at death's door the liveliest thing on
  screen, which is both wrong and horrible to look at.
- **`vitality` gates every social term, and this was a real bug found by its own test.** The first
  version let a friendly cursor cancel most of the misery of an empty hunger bar: a zen fish starving to
  death read as *mildly put out* (valence -0.15). Comfort helps an animal that is basically all right
  and does not help one that is dying, so the post-meal glow, attention and most of the temperament bias
  now scale with how fed the pet is. Temperament is suppressed only partly — fully would make all four
  personalities identical at the bottom.
- **Attention is asymmetric**: it rises over 20 s of the pointer being present and falls over 3 minutes
  of absence. A pet that forgot you the moment your cursor left would read as a state machine; one as
  slow to notice as to miss you would never react to a passing visit.
- **Loneliness is about absence, not about being sad.** It was first gated on low valence, which meant
  an optimistic personality could never be lonely at all. A cheerful pet can still miss you.
- **Where the state lives: the scene, not the store.** Attention has to advance every rendered frame,
  and a store write per frame would re-run every subscriber sixty times a second to move one number.
  Nothing else needs it, and it costs nothing to rebuild — a decaying accumulator converges within
  minutes of launch, which is also why nothing about the mood is persisted.
- **The mood only speaks when the simulation has nothing to say.** `moodAnim` returns `happy`,
  `excited`, `curious` or null, and the scene consults it only when the behaviour asked for `idle`.
  Eating, hunger posture, sleep and death are facts and outrank a feeling.
- **A feeling has to hold before it shows.** Moods are continuous and the labels read off them have
  boundaries, so a pet sitting on one asked for a different animation every tick and would have
  flickered between two poses eight times a second. `src/render/expression.ts` is the hysteresis: a new
  expression must be wanted for a full second before it is adopted, and dropping one is immediate —
  waiting to STOP looking excited would leave the pet grinning through a state change the simulation had
  just made, which reads as a bug where a delay before starting does not. Extracted from the scene
  rather than left inline precisely so it could be tested without a renderer.
- **Interest drives a micro-behaviour**: the fish bends its wander target toward the pointer, capped at
  55% so it drifts over and hangs about rather than tracking the cursor like a UI element. Gated to the
  content branch only — a hungry, sleeping or dead fish does not stop to investigate anything, and that
  is asserted rather than assumed.

### the chrome, restyled to match the art
The HUD pill, caption, speech bubble, dev panel and modal cards were pixel art too: Press Start 2P at

- A system typeface at 11 px, translucent dark pills with a backdrop blur, rounded controls, soft

### stage 3: the 3D art, wired in
27 renders became 68: the bowl split into layers, and all eight fish states rendered rather than three.

- **The bowl is four passes, not one image.** A single composite would have forced the fish to draw on
  top of the glass — its specular streak and rim highlight included — which is the "fish looks like it's
  outside the tank" complaint arriving by a new route. `bg` holds everything behind the fish, `glass` is
  the front surface on alpha (median alpha 0.17, with highlights to 1.0), `decor_front` is the front
  gravel lip and the nearest plant blade. The layer stack already drew those two after the `pet` slot;
  nothing about the architecture changed, only the art that fills it.
- **Geometry is projected, not measured.** The bowl camera is orthographic with a known mm/px, so the
  waterline, gravel floor and inner ellipse come out of the 3D scene into `geometry.json` and are divided
  by the art scale. This is the fix for the CLASS of bug that produced the waterline problem, not another
  instance of it: a renderer knows where its own water is, where a colour test has to guess.
- **`surfaceY` is the NEAR edge of the surface, not its centre.** The water surface is an ellipse seen
  from slightly above, spanning rows 56..78 rather than sitting on one line. Clamping to the centre (67)
  would let the fish rise in front of the visible waterline — the same symptom as before, for a new
  reason. Only the near edge is under water in every column.
- **The body box got shorter, and that was a judgement call.** The rendered bowl has 61 logical px
  between surface and gravel where the painted one had 110. A box tall enough to contain the dorsal and
  pelvic fins would have left about 20 px of vertical travel and flattened the figure-eight — the exact
  failure that once made the fish swim in a straight line. `body.h` is 32 against a drawn height of 39,
  so the body proper stays in the water and the fins overlap the glass, which is what the box was always
  for. `w` is 50 against a drawn 59.
- **The Blender-projected `bodyBox` was not usable and was not used.** It disagreed with the pixels in
  both orientations — it reported the body extending below the fish's own alpha bounding box — so the
  collision box was measured from the shipped frames instead. Worth recording: a projected number that
  cannot be reconciled with the art is not a better number than a measured one.
- **Night became a tint rather than an overlay.** `night.png` was two flat colours cut to the OLD bowl's
  silhouette; against the render it was the wrong resolution AND the wrong shape. Tinting the habitat's
  own sprites multiplies the texture and so respects its alpha for free — aligned by construction, at
  any art resolution, with no file to keep in step. Starvation moved the same way when `medium`, the
  layer it used to tint, stopped existing.
- **`fx` moved below `decor_front` and `glass`.** Bubbles rise inside the water, so the front gravel and
  the glass's own highlights belong on top of them. It was the topmost slot, which did not matter when
  bubbles were 6 px pixel rings and does once the glass is a real reflective surface.
- **Three art test files were replaced, not relaxed.** They asserted hard alpha, a 38-colour palette and
  one row of frame-sized cells — all correct for pixel art, none satisfiable by a render. The new
  `habitatArt.test.ts` asserts what matters now: every layer is the same whole multiple of the grid,
  `opaqueRect` is still bg's alpha bbox exactly (the click-through guard), the glass is see-through
  enough to see a fish through, the memorial keeps the hit region in place, every state ships the frames
  it declares, nothing is clipped at a frame edge, the fish is centred on its mirror axis, and the water
  band leaves room to swim.
- **`water.test.ts` stopped hard-coding one bowl.** Every literal in it went stale the day the habitat
  was re-rendered, which is a test reporting that the art changed rather than that the maths broke. It
  derives from `BOWL_WATER_SHAPE` and `FISH_BODY` now.
- `tools/gen_bg.py`, `gen_fish.py` and `gen_placeholders.py` are retired with the art they produced.

### stage 4 (motion): why the pet did not flow
"Make it move smoothly and don't glitch" turned into an audit of the whole motion pipeline. Thirteen
distinct causes; these are the ones that mattered, and two of them were bad enough on their own.

- **The pet ran at 2 frames per second, in four-tick lurches.** The fallback timer that drives the
  scene when the browser throttles `requestAnimationFrame` ticked every 125 ms but only acted after
  400 ms of quiet, so the first firing that passed the gate was at 500 ms and ran FOUR simulation steps
  at once. Worse, 500 is an exact multiple of the tick, so the accumulator landed on zero every time
  and the interpolation added the previous round contributed *nothing*. For a window that is hidden at
  launch, unfocused and click-through — exactly what WebKit throttles — this was very likely the normal
  path rather than the exception. **Measured after the fix: 30 advances/s instead of 2, with the
  simulation at its correct 8 Hz.**
  - The gate was also on the wrong timestamp: `advance()` bumps `lastAdvanceAt`, so the watchdog was
    re-gating against its own output and could not distinguish "rAF is running" from "I ran a moment
    ago". It now gates on a timestamp only the ticker writes. Tuning the old constants could not have
    fixed it — a gate at or below the interval double-fires against healthy rAF, and above it the rate
    halves.
  - Same timer, second bug: `lastAdvanceAt` started at 0, so its first firing computed an elapsed time
    of "now", clamped to a second, and ran eight steps before the first frame anyone saw.
- **The art and the simulation disagreed permanently, not just during transitions.** The eight states
  were rendered from separate poses whose bodies sit at different heights in the frame, and every
  simulation constant was tuned against the idle art. Measured across all 62 frames: `hungry` sits
  4.9 px low, `dead` 9.6 px high. That is **4.25 px of a starving fish's belly drawn inside the gravel
  and 9.25 px of a dead fish's tail drawn above the waterline** — the exact failure the water clamp
  exists to prevent, arriving through the art rather than through the geometry, and invisible to every
  test in the repo. Fixed with a per-state registration offset measured from the art, which lands both
  within half a pixel of the boundary the simulation declares. That agreement is the evidence the
  numbers are right.
- **The motion was quantised below the smoothing.** `behavior.ts` and `water.ts` rounded every position
  to a whole grid px, and the fish's top vertical speed is 0.85 px/tick, so the honest sequence was
  160, 160, 161, 161, 162 — hold, ramp one px, hold. Position continuous, velocity an 8 Hz square wave.
  Rounding was a pixel-art contract, like `roundPixels` and `image-rendering: pixelated` before it.
  - **A render-layer filter was the wrong fix, and I built one before proving it wrong.** A spring soft
    enough to hide a 125 ms staircase (ω≈8) trails a darting fish by 12 grid px; one stiff enough not to
    (ω≈40) smooths nothing. Worse, `BITE_RANGE` is measured from the body box in the *simulation*, so
    any render-side lag makes the drawn fish lunge at water the flake has already left. The general
    form: a render-layer filter desynchronises the drawn pet from every simulation-side predicate, and
    the simulation is pure and can never know about it. Deleted.
  - Removing the rounding also made `water.ts`'s clamp genuinely convex for the first time. The old one
    used `floor`/`ceil`, whose image is a lattice, so the comment in `scene.ts` justifying interpolation
    by convexity was false when it was written. The row search became a solved interval: the body fits
    where the ellipse is at least `halfW` wide at both its top and bottom rows, which is a closed form.
  - `inside()` needed an epsilon to match. The region is closed, and `clamp` returns its exact extreme
    point; testing that same point with a strict `<= 1` fails about half the time on the last bit of
    the arithmetic. That is the pet pressed against the glass, which is a position it reaches constantly.
- **Two "glitches" were facing bugs, not position bugs.** `moveToward` already caps the step, so the
  position could not jump — but the HEADING could. The cursor pull dropped in one tick when the pointer
  left, and the wander wobble re-rolled in one tick every two seconds; either could cross the turn
  threshold and throw a 125 ms spin that had nothing to do with where the fish was going. Both are now
  eased. A third: a starving fish drifts at 0.3 against a turn threshold of 0.4, so the inference never
  fired and it swam backwards half the time — its facing is now set from the intent when the drift is
  re-rolled, rather than inferred from a velocity too small to read.
- **The hungry band measured its floor and its ceiling in different spaces** — one accounted for the
  body box and one did not — giving a band 2.3 px tall. Derived from the legal centre range now.
- **The mood gate could not tell "stopped feeling happy" from "mid-bite".** Both arrived as a null
  request, so one bite dropped the expression instantly and then made the pet earn it back over a full
  second. It now holds while the simulation drives the pose.
- **Every frame was rendered twice**, once by `advance` and once by Pixi's ticker plugin at a lower
  priority. At the largest window that is a 2016x1536 target drawn twice for no benefit.
- Flakes stepped at 8 Hz beside an interpolated fish and dissolved by strobing `visible` at 4 Hz;
  bubbles blinked in and out at full alpha; the starving tint snapped in one frame and the night fade
  banded in eight discrete steps. All were the last stepped things in a renderer that had gone
  continuous everywhere else.

### the packaged app was running at ONE frame per second, and the timer fix alone did not find it
Fixing the fallback timer's gate took the throttled path from 2 fps to 30 in a browser. In the real
`.app` it changed almost nothing, and only measuring the built app revealed why.

**`document.visibilityState` is `hidden` in the packaged app while the window is plainly on screen.**
The window is never activated — a desktop pet must not steal focus, so the app uses the Accessory
activation policy and never calls `set_focus` — and WebKit treats an unactivated window as not visible.
For a hidden document it stops `requestAnimationFrame` entirely **and clamps `setTimeout`/`setInterval`
to once per second**. So the watchdog, whose whole job was to cover for a dead rAF, was itself clamped
to 1 Hz, each firing replaying a full second of simulation in one lurch.

- **A Worker has no visibility state, so its timers are not clamped.** `src/render/pacer.ts` runs a
  worker whose entire program is an interval that posts an empty message; all the work stays on the
  main thread, which the 1 Hz timer already proved was still processing tasks. Measured in the built
  app: **1 advance/s to 15**, and the simulation from 4.7 steps/s to 8.4 against a target of 8.
- It falls back to a plain interval if the worker cannot be created or never reports, and runs both
  until the worker proves itself. That is not superstition: this codebase has been bitten by a worker
  before — Pixi's texture loader ran in a blob worker whose `fetch` could not reach `tauri://` and
  every texture failed silently. This worker fetches nothing, so that failure does not apply, but a
  fallback costing three lines is cheap against being wrong about that twice.
- **15 fps, not 60, and the rest is a platform behaviour rather than a cost.** Render time is 1.2 ms per
  frame, so nothing is slow; WebKit simply delivers a hidden document's worker messages in bursts. A
  33 ms interval yields ~12/s and 8 ms yields ~18/s, so the interval matters and it is not a hard
  clamp, but chasing the last few frames means a wakeup every 8 ms forever for a pet idling in a corner.
- **The general lesson, which is the second time this exact thing has happened here:** Pixi's `fps` is
  seeded to 60 and only corrected by a tick, so on precisely the failure worth catching it reports 60
  while nothing runs. The boot report now samples the scene's own advance counter across a known
  interval and records `document.visibilityState`, which is what turned "it feels glitchy" into a
  number.

### window layering: float, desktops, and fullscreen
`alwaysOnTop` was a static line in the window config and `set_visible_on_all_workspaces(true)` was
fired once, unconditionally, at startup. Neither could be turned off. Both are settings now, plus a
third the app never asked for.

- **Applied as a set, not one switch at a time.** On macOS these are facets of two window properties —
  the level and the collection behaviour — and the collection behaviour is a bitmask that has to be
  read, modified and written. One command applying all three keeps that read-modify-write in one place.
- **"Show over fullscreen apps" is the project's first native code.** macOS gates it behind
  `NSWindowCollectionBehaviorFullScreenAuxiliary`, which neither Tauri nor the windowing layer under it
  exposes, and a high window level alone is not enough: a fullscreen app gets its own Space and a window
  that has not asked for this flag simply is not there. `objc2-app-kit` was already in the lock file as
  a transitive dependency, so this adds no new graph.
- **No settings version bump.** `normalizeSettings` fills a missing field from the defaults but returns
  defaults *wholesale* for a version it does not recognise, so bumping to add three booleans would have
  discarded every existing user's mute, day/night and launch-at-login preferences. Two persistence
  tests that pinned exact settings literals now spread over `defaultSettings()`, so the next field
  added shows up as "takes its default" rather than as a failure.
- Switching all-desktops off has a side effect worth knowing: on macOS that same collection behaviour
  is what stops Stage Manager shrinking and re-arranging the window like an app window.

### the scale became continuous, as an integer count of eighths
The three-rung ladder existed because only whole multiples of the grid were legal while the renderer
drew on a pixel grid. That constraint went with the pixel art, so the scale is now continuous between
0.75x and 4x, reachable from a drag handle and from +/- buttons on the hover bar as well as the tray.

- **Eighths, not a float.** `GRID_W` and `GRID_H` are both divisible by 8, so `windowSizeForScale` is
  `40n + 48` by `30n + 48` — exact whole pixels for every value, in both languages, with no rounding
  rule to keep in step and no reliance on two JSON parsers agreeing about a decimal. The alternative,
  sending a float and rounding "in exactly one place", is a rule someone has to maintain; this is a
  property of the numbers. A one-pixel disagreement between Rust and the frontend silently stops the
  click-through region matching the art, and the symptom is the window eating clicks meant for the app
  behind it — which is miserable to trace back to a rounding difference.
- **The contract test gained a better assertion than the one it lost.** The old one checked that the
  rung list was a contiguous ascending run, which existed only because Rust expressed three rungs as a
  range. The new one asserts `GRID_W % SCALE_STEPS_PER_UNIT == 0` on both sides, which is what turns
  "the two languages agree to the pixel" from a hope into a theorem.
- **The handle is at the habitat's TOP-LEFT**, which is unconventional and correct here: resizing pins
  the window's bottom-right, because this is a corner pet that lives in the bottom right of a screen,
  so that is the corner that travels with the cursor. A handle at the bottom-right would sit still
  while the window grew away behind it.
- **It is a DOM element, not something drawn into the canvas**, and that is not a style preference:
  `main.ts` starts a native window drag on any `mousedown` over the canvas, which hands the mouse to
  the window server and stops the webview seeing another event. A handle drawn there could be pressed
  but never dragged.
- **The cursor poller has to stand down during a drag.** The window is click-through outside its hit
  regions, enforced by a poller that toggles ignore-cursor-events; mid-drag that takes the pointer away
  from the element that captured it and the drag dies with the window stuck at whatever size it had
  reached. The lock is a renewed DEADLINE rather than a flag, because the release is the dangerous
  half: a swallowed pointerup would otherwise leave the transparent padding permanently opaque and the
  user unable to click their own desktop again.
- **A live drag skips snapping and skips persisting.** Snapping moves the window by up to 16 px, which
  detaches the handle from the cursor; persisting calls `store.save()`, and a drag produces a step every
  few pixels of travel. Both happen once, on release, through the normal `setScale` path.
- **Settings: the field was renamed, not versioned.** `scale` now counts eighths, so a stored `2` would
  read back as a quarter of a rung — a 128x108 window. It is written as `scaleSteps` and the old key is
  read as a legacy rung. Bumping the version instead would have hit `normalizeSettings`'s "unknown
  version, return defaults" branch and discarded every other preference.
- Small, Medium and Large are still 1x, 2x and 3x, so nobody's window changes size on upgrade. The
  keyboard shortcuts now step by a quarter of the grid rather than jumping between rungs: at one eighth
  the range is 26 presses end to end, which is not a shortcut.
